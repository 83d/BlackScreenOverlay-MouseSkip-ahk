# BlackScreenOverlay-MouseSkip-ahk

在 Windows 双屏桌面中，用黑色窗口遮住副屏左侧区域，并让鼠标双向跳过该区域。脚本使用 AutoHotkey v2，适合主屏在左、副屏在右的布局。

## 当前脚本

| 文件 | 配置 |
| --- | --- |
| [screen2-left-800px.ahk](./screen2-left-800px.ahk) | 副屏左侧 800px 黑色遮罩，鼠标双向跳过 |

目前只提供 800px 版本，其他宽度的脚本后续按需添加。

## 工作方式

```text
┌───────────────┐ ┌───────────────┬─────────────────┐
│     主屏      │ │ 副屏左侧黑区  │ 副屏可见区域    │
│               │ │     800px     │                 │
└───────────────┘ └───────────────┴─────────────────┘
               ────── 向右跳过 ──────→
               ←───── 向左跳过 ──────
```

- 从左侧跨入黑区，鼠标跳到黑区右侧。
- 从右侧跨入黑区，鼠标跳到黑区左侧。
- 跳转只修改 X 坐标，传入的 Y 坐标保持不变。
- 黑色遮罩覆盖目标显示器左侧的整个高度。

脚本通过定时检查鼠标位置实现跳转，不是硬件级鼠标屏障。黑框只是覆盖内容，不会改变显示器分辨率或应用窗口布局。

## 使用条件

- Windows 11。
- 已安装 [AutoHotkey v2](https://www.autohotkey.com/)，不支持 v1。
- 至少两块显示器，使用扩展桌面模式。
- 当前版本按“最靠右的非主显示器”选择目标，不按 Windows 显示设置中的编号强制选择显示器 2。
- 目标副屏宽度应大于 800px；主屏应紧邻副屏左侧，且需要穿越的位置处于两屏共有的高度范围内。否则黑区左侧可能没有有效屏幕坐标，Windows 可能会限制或调整鼠标落点。

## 启动与退出

1. 下载 `screen2-left-800px.ahk`。
2. 双击脚本运行，副屏左侧会出现黑框。
3. 分别从左右两侧移入黑区，检查双向跳转效果。
4. 按 `Ctrl + Alt + F12` 退出，也可以通过 AutoHotkey 托盘图标选择 Exit。

| 快捷键 | 功能 |
| --- | --- |
| `Ctrl + Alt + F11` | 显示或隐藏黑色遮罩；鼠标跳转仍然启用 |
| `Ctrl + Alt + F12` | 退出脚本，关闭遮罩与鼠标跳转 |

脚本不会写入注册表、安装驱动或修改显示器配置。退出后，遮罩消失，脚本不再干预鼠标移动。

## 配置

可在脚本开头修改以下参数，保存后重新运行：

```ahk
deadZoneWidth := 800  ; 黑区宽度，按物理像素设计
showBlack := true    ; 启动时显示遮罩；false 表示仅启用鼠标跳转
```

当前文件名对应 800px 配置。重新运行同一路径的脚本会替换原实例；如果复制或改名后运行，请先退出旧脚本，避免多个实例同时干预鼠标。

## 当前限制

- 修改显示器排列、分辨率或缩放后，需要重新运行脚本以读取新的边界。
- 跳转依赖前一次采样的 X 坐标判断进入方向。鼠标启动时已经在黑区中，或从黑区上方、下方进入时，当前逻辑可能无法将其移出。
- 定时采样存在延迟，不能保证每一帧都看不到黑区内的指针。
- 遮罩为置顶且点击穿透的普通窗口，不会阻止所有方式对下层应用的操作，也不保证覆盖独占全屏应用或系统安全桌面。
- 不同缩放、显示器布局和全屏应用下的效果需要实际验证。

## 右侧 1800px 版本（新脚本）

如果您的布局与截图类似，屏幕 2 位于主屏右侧，并希望把屏幕 2 的**最右侧 1800px**作为黑色遮罩和鼠标跳过区，请运行 [screen2-right-1800px.ahk](./screen2-right-1800px.ahk)。该脚本会自动选择“最靠左的非主显示器”（适合副屏位于主屏左侧），读取当前显示器边界，并在右侧创建遮罩。

```text
主屏        屏幕2
┌──────┐ ┌─────────────────┬──────────────┐
│      │ │   可见区域      │ 黑区 1800px  │
└──────┘ └─────────────────┴──────────────┘
                         ← 进入黑区时退回
```

### 给修改脚本的说明

1. 复制一个 `.ahk` 文件再修改，保留 `#Requires AutoHotkey v2.0`，不要混用 v1 语法。
2. `deadZoneWidth` 是黑区宽度，按屏幕坐标像素填写；右侧版本使用 `deadL := Max(targetRight - deadZoneWidth, targetLeft)` 计算左边界。
3. 左侧版本把黑区放在 `targetLeft`，右侧版本把黑区放在 `targetRight`；修改位置时要同步调整 `deadL`、`deadR` 和 `WatchMouse()` 中的跳转方向。
4. 右侧 1800px 版本按“最靠左的非主显示器”寻找屏幕2，适用于副屏位于主屏左侧的布局；原左侧版本仍按最靠右的非主显示器选择。如果要固定某个显示器，请改写选择显示器的循环，并保留 `MonitorGet()` 返回的坐标逻辑。
5. 修改后双击运行测试；`Ctrl + Alt + F11` 切换遮罩，`Ctrl + Alt + F12` 退出。显示器排列、缩放或分辨率改变后，请重新运行脚本。

新增脚本不会修改或删除原来的 `screen2-left-800px.ahk`。


### 防止显示器方向判断错误

Windows 的“显示器 1/2”编号不等于显示器在桌面上的左右位置，`MonitorGet()` 返回的坐标才是实际布局依据。修改脚本前，应先读取每块显示器的 `left/top/right/bottom`：

- 副屏在主屏右侧：副屏的 `left` 通常等于或大于主屏的 `right`；左侧黑区从 `targetLeft` 开始。
- 副屏在主屏左侧：副屏的 `right` 通常等于或小于主屏的 `left`；右侧黑区从 `targetRight - deadZoneWidth` 开始。
- 不要仅凭“显示器编号”或屏幕设置页面中的视觉顺序选择目标。
- 如果存在三块或更多显示器，应优先选择与主屏边界相邻的那一块，而不是盲目选择最左或最右的一块。

验证脚本时，先在命令行读取实际边界，再确认 `deadL`、`deadR` 是否落在预期显示器上。更改显示器排列、分辨率或缩放后，也应重新读取并测试。

## 设计脚本时的通用思路

显示器拼接方式不是固定的，不能把“屏幕 2”简单理解成主屏右边的一块屏幕。实际布局可能是左右排列、上下排列、错位排列，也可能有三块或更多显示器。README 不可能列出全部组合，因此修改脚本时应遵循下面的思考顺序：

1. **先读取事实，再写判断。** 使用 `MonitorGetCount()`、`MonitorGetPrimary()` 和 `MonitorGet()` 读取每块显示器的坐标与尺寸。不要根据 Windows 的显示器编号、设备名称或设置页面中的图形位置猜测方向。
2. **把显示器当作坐标矩形。** 每块屏幕都有 `left/top/right/bottom`。通过矩形边界判断屏幕之间是否相邻，以及相邻发生在左、右、上还是下；还要检查两块屏幕在另一条轴上的投影是否有重叠。
3. **明确目标和策略。** 多屏环境中，先确定要处理哪一块显示器（最好提供配置项或按与主屏的邻接关系选择），再确定黑区位于哪条边。不要用“最左”或“最右”作为通用规则。
4. **让跳转方向与黑区边界一致。** 黑区在左/右边时改变 X 坐标，在上/下边时改变 Y 坐标；跳转前要判断鼠标是从黑区哪一侧进入，并保持另一条坐标尽量不变。
5. **处理不规则布局。** 三屏以上、上下错位、部分边界相接或屏幕之间有间隙时，不能假设鼠标一定能直接跨越。没有有效邻接屏幕时，应保持鼠标在当前屏幕或给出提示，而不是把坐标强行移到未知位置。
6. **用实际坐标验证结果。** 修改后打印或显示目标屏幕边界、黑区边界和跳转落点，确认它们确实位于预期矩形内。调整分辨率、缩放或排列后必须重新验证。

这些原则是扩展脚本的基础；新增布局时，应先画出显示器坐标矩形和鼠标路径，再修改选择逻辑与 `WatchMouse()`，而不是只替换几个数字。

## 必须先确认“针对哪块屏幕”

如果用户只说“在副屏创建黑色遮罩跳过层”，但没有明确屏幕编号，AI 应先追问：**黑色遮罩跳过层针对 Windows 显示设置中的屏幕 1、屏幕 2，还是其他屏幕？黑区位于该屏幕的哪一条边？** 在目标未明确前，不应自行猜测或直接修改脚本。

建议引导用户打开：**桌面右键 → 显示设置**。点击“标识”后，Windows 会在每块显示器上显示屏幕编号；同时可看到各屏幕的左右、上下排列关系。用户提供这张界面截图，或直接说明“屏幕 2 在屏幕 1 左侧/上方”等信息，通常最可靠。

### 命令行读取编号时的注意事项

AutoHotkey 的 `MonitorGet()` 可以读取所有显示器的数量、坐标和尺寸，但它返回的枚举索引不保证等于 Windows 设置页面显示的“屏幕 1/2”编号。PowerShell/WMI 也常能读取设备名称、分辨率和部分显示信息，却不一定提供与设置页面编号稳定对应的映射。**因此，坐标适合判断物理布局，不能单独用来确认用户所说的“屏幕 2”编号。**

通用脚本应把“Windows 显示器编号”和“实际坐标矩形”视为两个不同概念：先让用户确认目标编号，再通过设备信息或坐标关系定位对应显示器，并在启动时显示目标屏幕的边界供用户核对。若无法建立可靠映射，应提示用户确认，而不是静默选择一块屏幕。

## 本项目中的屏幕术语约定

为避免沟通歧义，本项目约定：

- **屏幕 1 / 主屏 / 主显示器**：用户在“显示设置”中确认的主显示器。
- **屏幕 2 / 副屏 / 副显示器**：用户在“显示设置”中确认的目标副显示器。

在常见的 Windows 配置中，屏幕 1 通常也是主屏，屏幕 2 通常是副屏；但编写通用脚本时仍应以用户在“显示设置”中点击“标识”看到的结果为准。命令行中的 `\\.\DISPLAY1`、`\\.\DISPLAY2` 是设备名称，不是这里约定的“屏幕 1”“屏幕 2”，两者可能顺序相反。

因此，需求描述应尽量明确为：“针对显示设置中的屏幕 2（副屏）”，并同时说明黑区位于该屏幕的左、右、上或下侧。脚本内部再将这个目标映射到实际的坐标矩形。

### 鼠标双向跳转的方向规则

以当前 `screen2-right-1800px.ahk` 为例：屏幕 2 在屏幕 1 左侧，黑区位于屏幕 2 的右边，并且黑区右边界贴近屏幕 1。此时必须按鼠标进入黑区前的方向处理：

- 鼠标从屏幕 2 可见区域向右进入黑区：跳过黑区，落到屏幕 1 的左侧坐标（`deadR + 1`）。
- 鼠标从屏幕 1 向左进入黑区：跳过黑区，落到屏幕 2 可见区域（`deadL - 1`）。

判断方向依赖定时器上一次记录的 `previousX`（上下黑区则对应使用 `previousY`）。不能因为黑区叫“右侧”就让两个方向都跳到黑区左边；跳转落点必须位于黑区外，并且位于进入方向的另一侧。修改 `WatchMouse()` 后，应分别从黑区两侧测试进入，确认鼠标确实能往返跨屏。
